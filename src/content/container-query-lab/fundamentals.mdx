## 1. O Problema Histórico das Media Queries

Durante mais de uma década, a responsividade na web operou sob uma suposição falha: que a largura da tela do dispositivo (o *viewport*) dita a aparência de cada componente dentro dela.

Considere um componente simples de **Card de Produto**:
- Em um smartphone (360px), o card deve ser **vertical** (imagem no topo, texto embaixo).
- Em um desktop (1200px), o card deve ser **horizontal** (imagem à esquerda, texto à direita).

O que acontece quando você reutiliza esse mesmo card na **barra lateral** (sidebar) do desktop que tem apenas 280px de largura?
Com `@media (min-width: 1024px)`, o card pensa que está em um desktop gigante e renderiza seu layout horizontal dentro de uma coluna minúscula de 280px, **destruindo o layout e transbordando o texto**.

```
Viewport 1200px (Desktop):
┌─────────────────────────────────┬──────────────────┐
│ Área Principal (850px)          │ Barra Lateral    │
│ [Card Horizontal: Funciona bem] │ [Card Quebrado!] │
└─────────────────────────────────┴──────────────────┘
```

## 2. A Mudança de Paradigma

Com **Container Queries**, viramos a responsabilidade de cabeça para baixo:

> Um componente **não deve saber** qual é a resolução do monitor do usuário. Ele deve saber apenas **quanto espaço seu contêiner pai lhe forneceu**.

```css
/* O pai cria o contexto de contenção */
.sidebar-slot {
  container-type: inline-size;
}

/* O card responde ao contêiner, não à tela! */
@container (inline-size > 500px) {
  .product-card {
    display: grid;
    grid-template-columns: 200px 1fr;
  }
}
```

Agora, se o card estiver na área principal (850px), ele se torna horizontal. Se for movido para a barra lateral (280px), ele automaticamente se recolhe para vertical, **mesmo em um monitor de 4K!**

<Callout type="info" title="Baseline Universal">
  Container Queries de dimensão possuem suporte nativo de 100% em todas as engines modernas de navegadores desde 2023.
</Callout>

## 3. O Conceito de Contenção (CSS Containment)

Por que a W3C levou tantos anos para implementar Container Queries?
A resposta é: **loops infinitos de renderização** (*Layout Trashing*).

Se um componente filho muda de tamanho com base no pai, mas o tamanho do filho altera a altura ou largura do pai, o navegador entraria em um loop eterno recalculando o layout 60 vezes por segundo.

Para resolver isso, a especificação exige que contêineres ativem a **Contenção de Layout** (`contain: layout` ou `container-type: inline-size`). Isso informa ao motor C++ do navegador que as mudanças geométricas internas do contêiner não devem vazar para o documento externo.

/>

## 5. Boas Práticas

1. **Separe o contêiner do componente**: O elemento hospedeiro (*host*) declara `container-type: inline-size`, e o elemento filho consome `@container`.
2. **Utilize sempre `inline-size`**: Permite que o contêiner cresça livremente em altura enquanto responde apenas à largura horizontal.
3. **Evite acoplamento com a árvore global**: Nenhum seletor dentro de um `@container` deve referenciar IDs globais de páginas.
