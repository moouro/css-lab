## 1. Conceito

No web design tradicional, costuma-se escrever `@media (min-width: 768px)` para colocar uma barra lateral ao lado do conteúdo. Mas se esse componente for colocado dentro de uma coluna de 400px em um layout complexo, ele quebrará terrivelmente porque a viewport é larga mas o container é estreito!

O **Sidebar** do *Every Layout* é um layout quântico: ele existe em dois estados (lado a lado ou empilhado) determinados estritamente pelo espaço que o container disponibiliza para os dois irmãos.

## 2. A Mecânica do Algoritmo

O segredo está na distribuição do espaço residual com valores contrastantes de `flex-grow`:

```css
.with-sidebar {
  display: flex;
  flex-wrap: wrap;
  gap: var(--space-m);
}

.with-sidebar > :first-child {
  /* A barra lateral */
  flex-basis: 18rem;
  flex-grow: 1;
}

.with-sidebar > :last-child {
  /* O conteúdo principal */
  flex-basis: 0;
  flex-grow: 999;
  min-inline-size: 50%;
}
```

### Como a matemática do browser funciona:
1. O conteúdo principal tem `flex-grow: 999`, consumindo praticamente todo o espaço livre após o `flex-basis: 18rem` da sidebar ser reservado.
2. Quando a tela encolhe e o conteúdo principal tem menos de `50%` do espaço total disponível (`min-inline-size: 50%`), a regra de flex-wrap é disparada.
3. Ambos quebram para linhas separadas e agora ocupam `100%` da largura cada um. Zero media queries!

<AntiPattern
  badCode={`/* Frágil: depende de breakpoints de tela rígidos */\n@media (min-width: 900px) {\n  .sidebar { width: 250px; float: left; }\n  .main { width: calc(100% - 250px); float: right; }\n}`}
  goodCode={`/* Resiliente: adapta-se a qualquer container */\n.sidebar { flex-basis: 18rem; flex-grow: 1; }\n.main { flex-basis: 0; flex-grow: 999; min-inline-size: 50%; }`}
