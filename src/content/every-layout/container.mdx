## 1. Conceito

No Every Layout 3ª Edição, os autores respondem à grande dúvida da comunidade: *"Agora que temos Container Queries, o Every Layout está obsoleto?"*

A resposta enfática é **não**. Container Queries continuam sendo uma forma de intervenção manual (um *disjuntor*). Onde você pode usar Flexbox, Grid ou Switcher intrínsecos com matemática do browser, você escreve menos código e com maior compatibilidade retroativa. O **Container** serve como a nossa **válvula de escape definitiva** quando a resiliência intrínseca pura não for suficiente.

## 2. A Sintaxe Moderna

```css
.container-query {
  container-type: inline-size;
}

.container-query[data-name] {
  container-name: var(--container-name);
}

/* Consultando o container */
@container (width > 400px) {
  .card-media {
    display: flex;
  }
}
```

<Callout type="warning" title="Cuidado com Loops de Contenção">
  Sempre use `container-type: inline-size` em vez de `size` completo, a não ser que o container tenha uma altura explicitamente fixada. Usar `size` faz o elemento ignorar a altura do seu próprio conteúdo!
</Callout>

<AntiPattern
  badCode={`/* Desnecessário: usar CQ para o que o Flexbox já faz sozinho */\n.box { container-type: inline-size; }\n@container (max-width: 400px) {\n  .item { width: 100%; }\n}`}
  goodCode={`/* Resiliente: Flex-wrap nativo sem consultas */\n.cluster {\n  display: flex;\n  flex-wrap: wrap;\n}`}
  explanation="Reserve Container Queries para casos onde o estilo visual dos filhos precisa mudar drasticamente (ex: alterar tamanho de fonte ou trocar ordem de exibição estrutural), e não para mero empilhamento de fluxo."
/>
