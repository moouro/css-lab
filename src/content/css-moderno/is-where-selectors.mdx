## 1. Conceito

Tanto `:is()` quanto `:where()` recebem uma lista separada por vírgulas de seletores e aplicam as regras aos elementos que correspondem a qualquer um dos itens da lista.

Antes deles, estilizar múltiplos elementos dentro de seções diferentes exigia uma matriz verbosa:

```css
/* Antigo e repetitivo */
header h1, header h2, header h3,
main h1, main h2, main h3,
article h1, article h2, article h3 {
  line-height: 1.2;
}

/* Moderno com agrupamento */
:is(header, main, article) :is(h1, h2, h3) {
  line-height: 1.2;
}
```

## 2. A Diferença Crucial: Especificidade

A única diferença fundamental entre `:is()` e `:where()` é como o algoritmo da cascata calcula a **especificidade**:

| Pseudo-classe | Cálculo de Especificidade | Caso de Uso Ideal |
| :--- | :--- | :--- |
| `:is(...)` | Assume a especificidade do **seletor mais pesado** da lista | Componentes e seletores de aplicação |
| `:where(...)` | Especificidade é **SEMPRE ZERO** (0, 0, 0, 0) | Resets, defaults de Design System e temas |

### Exemplo Prático de Especificidade

```css
/* Especificidade de :is(): herda o peso do #special-button = (1, 0, 0) */
:is(button, .btn, #special-button) {
  padding: 1rem;
}

/* Especificidade de :where(): É ZERO! Qualquer classe sobrescreve com facilidade */
:where(button, .btn, #special-button) {
  padding: 1rem;
}

/* Esta classe simples (0, 1, 0) VENCE o seletor :where() acima, mesmo com ID dentro dele! */
.custom-padding {
  padding: 0.25rem;
}
```

<Callout type="info" title="O Superpoder de :where() em Design Systems">
  Criadores de Design Systems e bibliotecas usam `:where()` para fornecer estilos padrão que os consumidores da biblioteca conseguem sobrescrever com uma única classe simples, sem nenhuma guerra de especificidade.
</Callout>

## 3. Tolerância a Falhas (Forgiving Selector Parsing)

Em seletores CSS clássicos, se um único item da lista for inválido ou não suportado pelo navegador, a **regra inteira é descartada**:

```css
/* Se o navegador não reconhecer ::-moz-focus-inner, NADA recebe estilo */
button, button::-moz-focus-inner, button:focus-visible {
  outline: 2px solid blue;
}
```

Com `:is()` e `:where()`, o parsing é **indulgente** (*forgiving*):
```css
/* Se ::-moz-focus-inner for inválido, o navegador ignora apenas ele e estiliza o resto! */
:is(button, button::-moz-focus-inner, button:focus-visible) {
  outline: 2px solid blue;
}
```

## 4. Anti-patterns Comuns

## 5. Boas Práticas

1. **Use `:where()` para CSS Base e Resets**: Garanta especificidade 0 para tipografia padrão, botões e listas.
2. **Use `:is()` para regras de componentes funcionais**: Onde você deseja agrupar sem abrir mão da precedência normal de cascata.
3. **Aproveite a tolerância a falhas**: Agrupe seletores experimentais ou vendor-prefixed dentro de `:is()` para não quebrar navegadores modernos.
